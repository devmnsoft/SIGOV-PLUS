# RC50.68E-R3 — Esteira CI real de promoção

## Decisão executiva: **BLOCKED**

A R3 cria o workflow manual `.github/workflows/rc50-68-promotion.yml` para transferir os gates que
ficaram bloqueados na R2 a um runner GitHub Actions equipado. Criar e validar estaticamente o
workflow não equivale a executá-lo: a RC50.68 somente poderá ser marcada **PROMOVIDA** depois de
uma execução integralmente verde. A RC50.69 não foi iniciada.

## Como executar

1. Configure o repository secret `SIGOV_CI_DB_PASSWORD` com uma credencial efêmera exclusiva de
   CI. O preflight verifica somente se o valor existe, nunca o imprime.
2. No GitHub, abra **Actions → RC50.68 promotion → Run workflow**, selecione o commit candidato e
   dispare o `workflow_dispatch`.
3. Exija o sucesso dos jobs `Secret preflight` e `Real promotion gates` e preserve o link da run
   como evidência de promoção. Ausência do secret resulta explicitamente em **BLOCKED**.

## Cobertura reproduzível

O job instala exatamente o SDK definido em `global.json` (10.0.100), inicia PostgreSQL 16 como
service container e valida `psql`, `pwsh` e actionlint. Em seguida executa clean/restore locked/build
do filtro runtime, parsing YAML/JSON/shell, integridade do CI, conflito de rotas, verificação do
gerador PowerShell e actionlint de todos os workflows.

O baseline `script_completop.sql` é aplicado duas vezes com `ON_ERROR_STOP=1`. A esteira lista
`sigov.schema_migrations`, exige as versões 20260820120000, 20260820160000, 20260820200000 e
20260820230000 e confirma, por joins persistidos, as dez permissões de contexto e as duas de
dashboard concedidas ao perfil sistêmico SUPERADMIN. Comparações byte a byte protegem os scripts
consolidados e scans simples rejeitam segredo literal, autoridade mock/demo/fallback e T-SQL
executável na superfície RC50.68.

## Critério de promoção

Até haver run verde real, o estado permanece **BLOCKED** e nenhum gate dinâmico é registrado como
PASS. Se a execução revelar erro SQL, a correção deverá ser uma migration idempotente nova, com
manifest, checksums e todas as cópias consolidadas sincronizadas; migrations publicadas não serão
alteradas.
