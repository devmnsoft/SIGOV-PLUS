# Promoção local assistida da RC50.68

Esta esteira executa homologação técnica real da RC50.68 em uma máquina do operador. Ela **não
substitui o CI oficial**, não consulta nem dispara GitHub Actions, não exige URL de run e não lê
`SIGOV_CI_DB_PASSWORD`. A promoção permanece **BLOCKED** até haver uma execução local integralmente
verde e o gate oficial aplicável também estar verde.

## Pré-requisitos

- SDK exatamente igual ao `global.json` (.NET 10) e PostgreSQL **16.x** acessível por `psql`;
- Node.js para validar `saas-authorization-admin.js`;
- Git e, no Linux, Bash; PowerShell 7 no Windows;
- um banco descartável cujo nome contenha `rc50`, `homolog`, `local`, `dev` ou `test`.

Defina no processo, sem gravar `.env` nem versionar segredo:

| Variável | Uso |
|---|---|
| `SIGOV_DB_HOST` | host PostgreSQL |
| `SIGOV_DB_PORT` | porta (normalmente `5432`) |
| `SIGOV_DB_NAME` | banco local/homologação com marcador seguro no nome |
| `SIGOV_DB_USER` | usuário com permissão para aplicar o baseline |
| `SIGOV_DB_PASSWORD` | senha, mantida somente no ambiente e nunca exibida |
| `SIGOV_WEB_URL` / `SIGOV_API_URL` | opcionais no smoke; padrões `http://localhost:5000/5001` |
| `SIGOV_LOCAL_AUTH_COOKIE` | opcional e efêmero; habilita apenas o smoke autenticado |

Não use um destino compartilhado ou real. Os scripts recusam `Production`, hosts cujo nome sinalize `prod`/`production` e bancos sem marcador de
homologação. `--confirm`/`-Confirm` é uma autorização explícita para **aplicar e reaplicar**
`script_completop.sql` no destino informado. A esteira não possui operação de drop; qualquer limpeza
do banco é responsabilidade separada do operador e nunca ocorre implicitamente.

## Linux

```bash
export SIGOV_DB_HOST=localhost SIGOV_DB_PORT=5432 SIGOV_DB_NAME=sigov_rc50_local
export SIGOV_DB_USER=sigov
read -rsp 'Senha PostgreSQL: ' SIGOV_DB_PASSWORD; export SIGOV_DB_PASSWORD; echo
./scripts/rc50-68-local-promotion.sh --confirm
```

Para incluir o smoke temporário de Web/API, acrescente `--smoke`. Somente em uma sessão local segura,
um cookie de autenticação efêmero pode ser fornecido em `SIGOV_LOCAL_AUTH_COOKIE`; o valor não é
registrado. Sem ele, a etapa autenticada fica corretamente `BLOCKED`.

## Windows (PowerShell 7)

```powershell
$env:SIGOV_DB_HOST = 'localhost'
$env:SIGOV_DB_PORT = '5432'
$env:SIGOV_DB_NAME = 'sigov_rc50_local'
$env:SIGOV_DB_USER = 'sigov'
$env:SIGOV_DB_PASSWORD = Read-Host 'Senha PostgreSQL' -MaskInput
./scripts/rc50-68-local-promotion.ps1 -Confirm
```

Use `-Smoke` para iniciar o runtime pelos scripts locais. Remova as variáveis sensíveis da sessão ao
terminar. Não copie a saída de `Get-ChildItem Env:` para as evidências.

## O que é validado

1. ferramentas, arquivos obrigatórios, variáveis mascaradas e PostgreSQL 16;
2. `git diff --check`, JSON e checksums do manifest, JavaScript, shell e YAML quando houver parser;
3. `dotnet clean`, restore locked e build Release com warnings como erros;
4. aplicação e reaplicação fail-fast do baseline, schema/ledger, tabelas RC50.68, checksums,
   permissões SuperAdmin e ausência de duplicatas nas autoridades centrais;
5. opcionalmente, health, recusa anônima de `/SaasAdmin/Autorizacao` e resposta autenticada sem 500.

## Evidências e interpretação

Cada execução recria `artifacts/rc50-68-local-promotion/` com:

- `result.json`: status por etapa, SHA validado, horário local e versões das ferramentas;
- `summary.md`: resumo executivo em formato auditável;
- `promotion.log`: saída sanitizada, sem senha, connection string completa ou cookie.

`PASS` comprova que a etapa foi executada com sucesso; `FAIL` comprova erro do produto, banco ou
validação e retorna exit code 1; `BLOCKED` significa ferramenta, conexão, confirmação ou credencial
ausente e retorna exit code 2. Ferramenta ausente nunca vira `PASS`. Mesmo que o JSON local fique
integralmente verde, o campo `promotion` continua `BLOCKED`: a decisão final requer o CI oficial.
